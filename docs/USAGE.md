# 使用说明

[返回项目介绍](../README.md) · [在线使用](https://krc.callmek.cn/)

## 浏览器与进入条件

| 入口 | 凭据 | 运行环境 |
| --- | --- | --- |
| 团支部（班级）端 | 本学期填报码 | 手机或电脑独立浏览器 |
| 年级端 | 本学期年级端密钥文件 | 电脑 Chrome / Edge，并授权本地工作文件夹 |
| 团委端 | 本学期团委端密钥文件 | 电脑 Chrome / Edge，并授权本地工作文件夹 |

请向系统管理员获取凭据，不要将密钥或包含学生信息的文件放入公开仓库。系统会核对密钥的学期、版本及有效性。

微信内置浏览器不作为支持环境：手机填报请转到手机系统浏览器，年级端和团委端请转到电脑 Chrome / Edge。浏览器标识可能存在差异；检测到文件夹接口不代表已经获得实际读写权限，仍需完成授权。

## 填报与任职

班级端选择书院、年级和班级，填写填报人信息，再录入学生干部信息。每个班级需要覆盖以下 10 个职务，一人可兼任多个职务：

- 团支部委员：团支部书记、组织委员、宣传委员、纪律委员、实践委员。
- 班级委员：班长、副班长、学习委员、文体委员、生活心理委员。

团支部书记须兼任班长，纪律委员须兼任副班长，系统联动对应任职。主职务编辑框分别使用独立名称，筛选和兼任选择使用组合名称。人员展示与导出优先排列团支部书记（班长）、纪律委员（副班长）。

选择主职务后才能选择额外兼任。职务已被他人担任时，可通过任职调整窗口交换或重新分配，不必先删人重录；确认前请核对涉及人员。系统检查重复学号、职务占用及覆盖情况。

## 导入与版本比较

班级文件交由年级端审核，年级文件交由团委端汇总；团委端也可直接导入班级文件生成通联表。

| 文件 | 命名形式 |
| --- | --- |
| 班级上报 | `C-{学期代码}-{书院代码}-{年级}-{班级代码}.lcq` |
| 年级上报 | `G-{学期代码}-{书院代码}-{年级范围}.lcq` |
| 汇总表格 | 考核结果汇总表、基层班团学生干部通联表（Excel） |

多文件导入支持分次添加、查看文件名、逐个移除和清空列表。系统按文件内容去重，同名但内容不同的文件分别保留；取消或失败的文件可以重试。

再次导入同一范围时：

1. 相同上报内容跳过，不覆盖本端的审核与修改。
2. 内容有变化时，比较当前数据、上次来源和新文件，展示新增、移除及修改项。
3. 本端修改与上报修改冲突时，默认保留本端，可逐项选择；确认后才更新。
4. 更早导出的文件会提示可能是旧版；更新仍需通过重复人员、职务与名额校验，保存失败会撤回本次更新。

团委端导入的年级范围部分重叠时，只更新本次涉及的范围。比较过程在本机完成，不将文件内容发送到服务器。

## 筛选与考核

年级、团委端顶部的工作区状态栏持续显示当前文件夹与保存状态。“工作区详情”按书院、年级分组，展开可核对已收及未收班级；团委端另行区分考核、本学期通联和历史通联数据。“设置”中可切换文件夹或取消授权，原有未保存提醒与操作确认继续生效。

年级审核工作台、团委考核明细支持多选筛选。同一项内的选择取并集，不同项之间取交集；点击“应用筛选”后生效，“取消”放弃本次选择，“清除筛选”立即恢复该项为全部。全选或未选也归并为全部，已应用的条件会突出显示。

年级端顶部工作区悬浮栏显示当前筛选条件、筛选人数与未评定人数。范围涉及一个年级时直接展示该年级的全年级名额；涉及多个年级时，点击“各年级名额”逐行查看。按班级、职务或等级缩小人员列表，不会缩小全年级名额的计算基数；此处的全年级基数指当前工作区已录入的该年级人员，不包含尚未导入的班级人数。

年级审核列表按年级完整分组并连续滚动，不按固定人数分页。筛选一个年级时，该年级的所有符合条件人员位于同一分组；同时查看多个年级时，各年级分别显示标题与人数。大量人员时，屏幕附近的编辑控件按需加载，正在输入或操作的卡片会保留。批量评定和“未评定一键合格”仍针对全部筛选结果，导出与名额计算不受屏幕当前显示位置影响。

名额以对应书院、年级范围内已录入的学生干部人数为基数：优秀人数上限为基数的 30%，优秀与良好合计人数上限为基数的 70%，两个上限均向下取整。批量评定按书院、年级分别校验名额，任一范围超额则不执行；批量设置的分数取对应职务在该等级下允许的最高分。存在不符合学生干部要求的情况时，原则上不评为优秀。

年级端逐人选择等级或分数后，系统立即校验并自动保存，不再弹出二次确认。添加人员、修改基础信息、批量评定与删除仍保留确认保护。保存状态显示在顶部；若写入失败，请保持页面打开并恢复文件夹访问后重试，页面中的待保存评定不会因此清空。导出前系统再次检查数据；导出后继续修改，需重新导出最新结果。

## 三端重复学号核对

班级端新增、编辑人员，年级端导入、添加人员及修改学号，团委端考核与通联导入、添加及编辑人员，均使用相同的重复学号核对窗口。

- 窗口列出冲突人员的姓名、学号、电话、职务、所属范围和可用来源信息，可修正本次填写或已有人员的姓名、学号、电话和备注；不会自动删人或覆盖记录来规避冲突。
- 导入时选择“确认修正并继续导入”，人员维护时选择“确认修正并继续保存”。未解决的重复或格式问题会阻止确认；后续版本比较、信息变更或任职调整仍按各自确认流程执行。
- “取消导入”放弃当前文件；“返回修改”回到尚未保存的填写界面。取消后已有数据保持不变；后续确认被取消时，此次纠错也不单独保存。
- 修改学号不改变既有考核等级和分数。纠错只作用于当前工作区，原上报文件和导入来源保留；再次导入仍进行版本比较。
- 保存失败会撤回本次新增或更新。添加人员的弹窗在保存成功后才关闭，失败时保留填写界面供核对和重试。

## 通联表核对与编辑

团委端导入班级文件生成通联表时，发现重复学号会打开核对窗口，列出相关人员的姓名、学号、联系电话、职务、所属范围及来源文件，并区分待导入内容与已有记录。重复涉及三人或更多人时，会全部列出。

1. 核对信息，在对应人员处修正学号；也可修正姓名、联系电话和备注。学号与电话均须为 11 位数字。
2. 所有重复与格式问题解决后，点击“确认修正并继续导入”。同范围更新仍需经过版本比较；最终数据通过校验后统一保存。
3. 点击“取消导入”或按 Esc，放弃当前文件的导入及本次纠错，不改变已有通联记录。批量导入按文件分别处理，先前已成功导入的文件保留。
4. 已导入人员可点击“编辑”修改基本信息、职务及备注，核对修改前后差异后确认保存。涉及他人任职时，按任职调整窗口交换或重新分配，不能直接覆盖他人职务。

通联表按书院、年级和班级提供多选筛选；下级选项随已应用的上级条件变化，选择、应用、取消和清除规则与考核筛选一致。页面显示当前筛选人数与总人数，**导出仍包含完整通联数据，不只导出当前筛选结果**。

修正仅保存到当前团委通联工作区，不改写原始 `.lcq` 文件，也不修改考核汇总中的记录。原始来源信息仍用于后续版本比较；如原上报有误，应同时通知填报人员修正其源数据。保存失败时撤回当前文件的更新或本次编辑，可检查文件夹权限后重试。

## 保存与恢复

- 班级草稿保存在当前浏览器中；年级端、团委端的工作数据保存到授权文件夹。浏览器草稿不能替代独立备份。
- 自动保存按顺序执行，确认保存成功后再关闭页面。保存失败或仍有待保存内容时，不要强制刷新、关闭或清除浏览器数据。
- 文件夹被删除、移动或权限失效时，页面提供恢复副本与切换文件夹等处理入口。恢复副本只包含当前页面仍持有的数据，不能找回未加载的已删除文件。
- 下载恢复副本后请核对下载是否成功；放入新工作文件夹时保留原文件名，使用对应密钥进入。切换文件夹需重新验证密钥。
- 换域名、换浏览器、换电脑或更换本地端口，不会自动迁移草稿、登录状态与文件夹授权。迁移前分别备份工作文件、上报文件和密钥。

## 学期与历史文件

登录密钥与数据密钥分离。同学期重置登录凭据保留数据密钥，验证新凭据后可继续使用原有同学期数据；缺少现用数据私钥时，系统会停止重置以保护已有数据。新学期需生成对应密钥包并发布配置。

切换学期后，年级端和团委考核汇总拒绝旧学期上报，不自动加载旧工作区；旧工作区文件不会自动删除，班级草稿也按学期校验。

团委端有两种历史数据用途：

- **历史上报文件**：解密只读查看班级或年级文件，不并入当前考核。不同学期或旧密钥版本需二次确认。
- **通联表**：允许经确认导入跨学期班级文件，保留来源学期，与本学期覆盖统计分开，不改变考核汇总。历史班级不因当前配置删除而从通联表导出中消失。

当前团委密钥包可整合本机已留存的历史解密信息，无需每次手动选择旧密钥。换电脑前，应在原浏览器验证管理员身份并重新下载当前密钥包。**从未留存或已经丢失的历史私钥，不能仅凭新私钥恢复。** 清空历史查看内容不会清除已留存的历史解密能力。

## Excel 与字体

导出标题使用方正小标宋简体 22 号，表头和正文中文使用仿宋_GB2312 16 号，数字使用 Times New Roman 16 号。姓名中未被字体字符表覆盖的字符使用仿宋替代。目标电脑需安装相应、合法取得的字体，缺少字体时表格软件可能替换显示。

两字中文姓名仅在导出时加入两个空格，三字及更长姓名保持原样，不修改系统中的原始姓名。页面输入控件使用界面字体，不套用公文字体。

## 缓存与更新

缓存完成后可在一定条件下离线使用，但离线期间无法即时获知新配置或凭据撤销。恢复联网后请刷新核对。更新后仍显示旧页面时，先保存工作，关闭该站点全部标签页再重新打开，不要为更新而清除全部浏览器数据。

## 数据边界

系统通过加密文件在各端之间传递业务数据，不进行多人实时同步编辑。人员信息与考核数据在浏览器中处理，保存至浏览器草稿、授权文件夹或导出文件；GitHub 保存代码和公开系统配置，私钥、令牌、学生名单及考核结果不应上传。

`.lcq` 用于标识系统的加密上报文件。文件保护依靠加密、校验及凭据的妥善保管，而非后缀名本身。
